What's changed

This page lists the changes to Boundaries Map that a reader would notice: new boundaries and features, data updates, and corrections when we published something wrong. Newest first. Routine reloads of boundary files that change nothing on the map are not listed.

  • History begins: 2018-08-20. The first version of the map was published that day. Entries before 2025 summarize releases, so smaller changes and corrections from those years may be missing.
  • Data refresh: by hand, from time to time. There is no fixed schedule, so a layer can fall behind the City's latest release.

The boundaries come from City, State and federal agencies, and the map shows them as those agencies publish them. When we find a problem in a source, we describe it here.

To report a bug in the map or ask for a new feature, open an issue on GitHub.

Election Districts did not match the City's current maps

October 19, 2026

Tags: Data, Correction

A State Assembly candidate told us that the Election Districts on the map did not match the City's official district maps. On October 19, 2026 we replaced them with City Planning's release 26C, published August 10, 2026. For example, Election District 24001, in Assembly District 24, was shown near Liberty Avenue and Rockaway Boulevard; it now sits near Union Turnpike and the Grand Central Parkway.

If you used the old numbers: The Election Districts layer was added on October 16, 2025, and the record does not show when it fell behind. If you looked up an Election District on the map before October 19, 2026, look it up again: compared with the old layer, 678 districts changed shape, 69 were removed and 19 are new. For official lines, check the City's own district maps.

Who it affects: Anyone who looked up an Election District, or which districts overlap one.

ZIP Codes now use the 2020 Census areas

October 19, 2026

Tags: Data

The ZIP Code layer now uses the 2020 Census ZIP Code areas published on NYC Open Data, in place of an older version built on 2010 areas. It has 221 areas instead of 178, including 11249 on the Williamsburg waterfront, and links to the ZIP Code layer still work. These areas are the Census Bureau's approximation of ZIP Codes, and in the City's file eight small slivers of ZIP Codes from outside the city fall inside its borders; the map shows them as published.

Who it affects: Anyone who uses the ZIP Code layer.

More detail: Pull request · The dataset on NYC Open Data

Overlaps for ZIP Codes in more than one piece listed some districts twice

July 8, 2025

Tags: Data, Correction

For a ZIP Code made of more than one piece, such as 10004, the overlap list showed the same district once for each piece. This was reported on March 6, 2024, and fixed on July 8, 2025, when the boundaries were rebuilt. Each district is now listed once.

If you used the old numbers: If you copied overlaps for a ZIP Code before July 8, 2025, count each district once. The record does not show when the problem started.

Who it affects: Anyone who looked up which districts overlap a ZIP Code made of more than one piece.

School Districts were mixed with Sanitation Districts

February 6, 2020

Tags: Data, Correction

Our data gave the School Districts and the Sanitation Districts the same name, so the School Districts layer also showed Sanitation Districts. The Sanitation Districts now have their own name, and the School Districts layer shows only school districts. A fix on January 6, 2020 was undone by mistake the same day, so the error lasted until February 6, 2020.

If you used the old numbers: The record points to November 18, 2019, when the map began reading every boundary from one combined file, as the start. If you looked up a School District, or which districts overlap one, between November 18, 2019 and February 6, 2020, the answer may have included Sanitation Districts. School District lines may have changed since, so check against the current map rather than trying to rebuild the old answer.

Who it affects: Anyone who used the School Districts layer in that period.

More detail: The fix · The first fix, undone the same day · The combined file
